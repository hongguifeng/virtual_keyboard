# ADR-006：MVP 以普通用户权限运行

状态：已采用（Accepted）

日期：2026-09-06

关联：方案设计文档 ADR-006、§15、§16.2；规格 NFR-SEC-001/002、AC-016/017、§10；T0.1

## 背景

UIPI（User Interface Privilege Isolation）会阻止低完整性进程向高完整性窗口发送输入。候选策略包括：自动提权 / 请求管理员 / 绕过 UIPI（调试权限、UI Automation 强制输入等）。这些方向均与“不绕过 UIPI”（NFR-SEC-001）冲突，或引入自动提权（非目标 NFR-SEC-002 明令禁止）。

## 决策

- MVP **以普通用户权限运行**，不请求管理员、不自提权、不要求 UAC 确认。
- **不绕过 UIPI**；UIA 仅用于发现/分类/验证，不作为输入路径。
- 向更高完整性窗口输入失败时，给出明确诊断“目标窗口权限高于本程序，输入被系统拒绝（UIPI）”，键盘保持可用（可隐藏/可移动/可暂停）（AC-016）。
- 系统输入桌面（UAC 弹窗、Win+L 锁屏等）明确属于非支持场景；用户可完全禁用程序（AC-017）。
- 诊断信息不得暴露目标窗口标题/内容/按键内容；密码目标不得记录 AutomationElement Name/Value（NFR-SEC-004）。

## 后果

- 优点：无 UAC 噪声、无提权供应链面；高完整性目标失败是明确受控边界而非静默丢失。
- 约束：高完整性窗口（部分 UWP/受保护进程）无法接收输入，需在用户文档说明；后续如需“受信任提权模式”须走独立 ADR + 安全评审。
